## 问题背景

在图像标注和OCR处理中，旋转矩形（Rotated Rectangle）有两种常见的存储方式：
- **OBB (Oriented Bounding Box)**：直接存储旋转后的顶点坐标
- **参数化旋转**：存储未旋转的矩形 + 旋转角度

X-AnyLabeling 使用 OBB 格式，而 BallonsTranslator 使用参数化旋转格式，导致直接转换会失败。

---

## 核心差异

### X-AnyLabeling 的存储方式（OBB 格式）

```json
{
  "points": [
    [323.36, 1043.65],  // 已经旋转后的顶点1（左上）
    [563.82, 996.59],   // 已经旋转后的顶点2（右上）
    [551.11, 931.67],   // 已经旋转后的顶点3（右下）
    [310.65, 978.73]    // 已经旋转后的顶点4（左下）
  ],
  "direction": 6.089,   // 旋转角度（弧度制）
  "shape_type": "rotation"
}
```

**特点：**
- 直接存储**旋转后**的四个顶点坐标
- 顶点按顺序排列（通常是左上→右上→右下→左下）
- 这是计算机视觉中标准的 OBB 格式

### BallonsTranslator 的存储方式（参数化旋转）

```json
{
  "lines": [[[345, 954], [597, 954], [597, 1028], [345, 1028]]],
  "angle": -11.66,
  "xyxy": [345, 954, 597, 1028],
  "_bounding_rect": [310, 949, 252, 74]
}
```

**特点：**
- `lines`: 存储**未旋转**的水平/垂直对齐矩形顶点
- `angle`: 旋转角度（度数，负值表示逆时针）
- `xyxy`: 旋转后的水平外接矩形（用于快速定位）
- `_bounding_rect`: `[x, y, width, height]` 格式的原始矩形

**关键理解：** `lines` 中的坐标是**未旋转状态**的矩形，渲染时才应用 `angle` 旋转！

## 转换逻辑

### 步骤1：从旋转后的顶点提取几何信息

```python
# 输入：4个旋转后的顶点
p1, p2, p3, p4 = points[0], points[1], points[2], points[3]

# 计算矩形的真实宽度和高度（两条邻边的长度）
width = math.hypot(p2[0] - p1[0], p2[1] - p1[1])   # 第一条边长度
height = math.hypot(p4[0] - p1[0], p4[1] - p1[1])  # 第二条边长度

# 计算旋转角度（使用 direction 字段或从顶点计算）
if 'direction' in shape:
    angle_rad = shape['direction']
    angle_deg = math.degrees(angle_rad)
else:
    angle_rad = math.atan2(p2[1] - p1[1], p2[0] - p1[0])
    angle_deg = math.degrees(angle_rad)

# 规范化角度到 [-180, 180] 范围
while angle_deg > 180:
    angle_deg -= 360
while angle_deg < -180:
    angle_deg += 360

# 计算中心点
center_x = sum(p[0] for p in points) / 4
center_y = sum(p[1] for p in points) / 4
```

### 步骤2：反向计算未旋转时的矩形位置 ⭐

这是**最关键**的一步！我们需要"反推"出如果这个矩形没有旋转，它原本应该在哪里。

```python
# 计算未旋转时的左上角坐标
unrotated_x = center_x - width / 2
unrotated_y = center_y - height / 2

# 生成水平对齐的矩形顶点（未旋转状态）
x1 = int(round(unrotated_x))
y1 = int(round(unrotated_y))
x2 = int(round(unrotated_x + width))
y2 = int(round(unrotated_y + height))

# 按标准顺序：左上→右上→右下→左下
unrotated_lines = [[[x1, y1], [x2, y1], [x2, y2], [x1, y2]]]
```

**为什么要这样做？**

想象一个旋转的矩形：
1. 我们知道它的中心点在 `(center_x, center_y)`
2. 我们知道它的尺寸是 `width × height`
3. 如果把它"转回去"到水平状态，左上角应该在中心点左上方 `(width/2, height/2)` 的位置

### 步骤3：计算外接矩形（用于快速定位）

```python
# 使用原始旋转后的顶点计算水平外接矩形
x_coords = [p[0] for p in points]
y_coords = [p[1] for p in points]
x_min, y_min = min(x_coords), min(y_coords)
x_max, y_max = max(x_coords), max(y_coords)

xyxy = [int(round(x_min)), int(round(y_min)), 
        int(round(x_max)), int(round(y_max))]

# _bounding_rect 使用未旋转的矩形信息
bounding_rect = [x1, y1, x2 - x1, y2 - y1]
```

### 步骤4：组装最终对象

```python
obj = {
    "xyxy": xyxy,                    # 旋转后的外接矩形
    "lines": unrotated_lines,        # 未旋转的矩形（关键！）
    "angle": angle_deg,              # 旋转角度
    "_bounding_rect": bounding_rect, # [x, y, width, height]
    "text": [""],                    # 空字符串触发OCR
    # ... 其他字段
}
```

## 为什么第一次失败

### ❌ 错误做法：直接使用旋转后的顶点

```python
# 错误：直接把旋转后的顶点放进 lines
lines = [[[323, 1043], [563, 996], [551, 931], [310, 978]]]
angle = 6.089
```

**问题：**
1. BallonsTranslator 拿到一个**已经旋转的四边形**
2. 然后又对它应用 `angle` 旋转
3. 结果就是**旋转了两次**！矩形位置完全错误
4. OCR 引擎无法正确识别，因为几何信息不匹配

### ✅ 正确做法：使用未旋转的矩形

```python
# 正确：提供水平对齐的矩形 + 角度参数
lines = [[[345, 954], [597, 954], [597, 1028], [345, 1028]]]  # 水平矩形
angle = -11.66
```

**效果：**
1. BallonsTranslator 拿到一个**水平矩形**
2. 应用 `angle` 旋转一次
3. 得到正确的旋转矩形位置
4. OCR 引擎可以正确识别文字区域

---

## 类比理解

想象你要描述一个倾斜放置的相框：

### 方法A（OBB）
"这个相框的四个角分别在坐标 (10,20)、(30,15)、(28,35)、(8,40)"
- ✅ 直接、精确
- ❌ 难以调整角度
- ❌ 不便于程序化处理

### 方法B（参数化旋转）
"这个相框原本在 (10,20) 位置，宽20cm，高20cm，然后逆时针旋转了15度"
- ✅ 便于编辑和调整
- ✅ 便于图形引擎渲染
- ✅ OCR 可以先"反旋转"再识别

BallonsTranslator 使用**方法B**，所以需要从**方法A**反推出参数。

## 完整代码示例

```python
import math

def convert_obb_to_parametric_rotation(points, direction=None):
    """
    将 OBB 格式转换为参数化旋转格式
    
    Args:
        points: 4个旋转后的顶点 [[x1,y1], [x2,y2], [x3,y3], [x4,y4]]
        direction: 旋转角度（弧度，可选）
    
    Returns:
        dict: 包含 lines, angle, xyxy, _bounding_rect 的字典
    """
    p1, p2, p3, p4 = points
    
    # 1. 计算宽度、高度、角度
    width = math.hypot(p2[0] - p1[0], p2[1] - p1[1])
    height = math.hypot(p4[0] - p1[0], p4[1] - p1[1])
    
    if direction is not None:
        angle_deg = math.degrees(direction)
    else:
        angle_rad = math.atan2(p2[1] - p1[1], p2[0] - p1[0])
        angle_deg = math.degrees(angle_rad)
    
    # 规范化角度
    while angle_deg > 180:
        angle_deg -= 360
    while angle_deg < -180:
        angle_deg += 360
    
    # 2. 计算中心点
    center_x = sum(p[0] for p in points) / 4
    center_y = sum(p[1] for p in points) / 4
    
    # 3. 反向计算未旋转的矩形
    unrotated_x = center_x - width / 2
    unrotated_y = center_y - height / 2
    
    x1 = int(round(unrotated_x))
    y1 = int(round(unrotated_y))
    x2 = int(round(unrotated_x + width))
    y2 = int(round(unrotated_y + height))
    
    unrotated_lines = [[[x1, y1], [x2, y1], [x2, y2], [x1, y2]]]
    
    # 4. 计算外接矩形
    x_coords = [p[0] for p in points]
    y_coords = [p[1] for p in points]
    xyxy = [
        int(round(min(x_coords))),
        int(round(min(y_coords))),
        int(round(max(x_coords))),
        int(round(max(y_coords)))
    ]
    
    bounding_rect = [x1, y1, x2 - x1, y2 - y1]
    
    return {
        "lines": unrotated_lines,
        "angle": angle_deg,
        "xyxy": xyxy,
        "_bounding_rect": bounding_rect
    }

# 使用示例
points = [
    [323.36, 1043.65],
    [563.82, 996.59],
    [551.11, 931.67],
    [310.65, 978.73]
]
direction = 6.089

result = convert_obb_to_parametric_rotation(points, direction)
print(result)
```

## 为什么 BallonsTranslator 要用参数化旋转？

### 1. 便于用户编辑
用户可以直接拖动角度滑块，只需修改 `angle` 参数，无需重新计算所有顶点。

### 2. 渲染效率高
图形引擎可以使用硬件加速的旋转变换，性能更好。

### 3. OCR 友好
OCR 引擎可以：
1. 根据 `angle` 反向旋转图像
2. 在水平状态下识别文字
3. 识别精度更高（大多数 OCR 模型对水平文本效果最好）

### 4. 数据更紧凑
只需存储 4 个参数（x, y, width, height, angle）而不是 8 个顶点坐标。

---

## 总结

**核心要点：**
1. OBB 存储的是**结果**（旋转后的顶点）
2. 参数化旋转存储的是**过程**（原始矩形 + 旋转操作）
3. 转换的关键是**反向计算**：从结果推导出过程
4. BallonsTranslator 需要未旋转的矩形才能正确进行 OCR

**记住这个公式：**
```
旋转后的矩形 = 未旋转的矩形 + 旋转角度
              ↓ 反向计算
未旋转的矩形 = 旋转后的矩形 - 旋转角度（反推中心和尺寸）
```
