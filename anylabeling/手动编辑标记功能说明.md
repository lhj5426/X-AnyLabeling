# X-AnyLabeling 手动编辑标记功能说明

**添加日期：** 2025-10-02
**功能概述：** 记录手动编辑过的标注文件，并在导出时支持仅导出手动调整的文件

---

## 功能概述

本功能为 X-AnyLabeling 添加了手动编辑标记系统，帮助用户区分 AI 自动标注和手动调整过的标注，并在导出 YOLO 格式时支持筛选导出。

### 主要功能

1. **自动标记手动编辑** - 当用户编辑标注时自动标记文件为"手动编辑"
2. **视觉标识** - 在文件列表中使用橙色标记手动编辑过的文件
3. **导出筛选** - 导出 YOLO 时可选择"仅导出手动调整的文件"

### 2. 自动标记编辑行为

**仅当用户手动执行以下操作时**，才会将 `manually_edited` 设置为 `true`：

- 移动形状
- 旋转形状
- 编辑顶点
- 添加/删除标注
- 修改标签
- 任何用户手动触发 `set_dirty()` 的操作

**重要：AI 推理不会标记为手动编辑**
- AI 自动推理的结果调用 `set_dirty(mark_as_manually_edited=False)`
- 这样可以区分 AI 自动标注和人工审核/修改的标注

**实现位置：**
- [label_widget.py:2485-2516](d:\Ddown\X-AnyLabeling-mogai1001_04\anylabeling\views\labeling\label_widget.py#L2485-L2516) - set_dirty() 方法定义

```python
def set_dirty(self, mark_as_manually_edited: bool = True):
    # 仅当参数为 True 时标记为手动编辑
    if mark_as_manually_edited:
```

## 技术细节

### 1. 存储机制

手动编辑标记存储在 JSON 文件的根级别字段中：

```json
{
  "version": "3.2.2",
  "manually_edited": true,  ← 根级别字段
  "description": "",
  "shapes": [...]
}
```

这样设计的优点：
- 不影响现有的 shapes 数据结构
- 兼容旧版本文件（默认为 false）
- 易于检查和筛选

### 2. 触发机制

所有用户交互导致的修改都会触发 `set_dirty()` 方法，该方法会：

1. 设置 `manually_edited = true`
2. 标记文件为"脏"（需要保存）
3. 如果开启自动保存，立即保存

```python
def set_dirty(self):
    self.other_data["manually_edited"] = True  # 标记为手动编辑
    if self._config["auto_save"]:
        self.save_labels(label_file)  # 自动保存
    else:
        self.dirty = True  # 标记为需要保存
```

### 3. 视觉反馈

文件列表项显示的更新时机：

- **加载文件夹时：** 读取所有 JSON 文件，检查 `manually_edited` 字段
- **保存文件后：** 更新当前文件的显示状态

```python
# 检查manually_edited标记
with open(label_file, 'r', encoding='utf-8') as f:
    data = json.load(f)
    manually_edited = data.get("manually_edited", False)

# 设置橙色
if manually_edited:
    item.setForeground(QtGui.QColor("#FFA500"))  # 橙色
```

## 重要修复：AI 推理覆盖手动标记

**修复日期：** 2025-10-03
**问题：** AI 重新推理后，手动编辑标记（橙色）没有被清除

### 问题场景

```
1. 老模型推理 → 识别错误（猫识别成狗）
2. 手动修正 → 改成"猫"，文件变橙色（manually_edited = true）
3. 换新模型重新推理 → 新模型能正确识别"猫"
4. 问题：文件仍然是橙色 ❌
5. 导出"仅手动调整的文件" → 错误地导出了新模型已经能识别准确的数据 ❌
```

### 核心逻辑

- **橙色（manually_edited = true）** = 当前模型推理不准，需要人工修正的数据
- **黑色（manually_edited = false）** = 模型推理结果（无论准不准）
- **AI 重新推理应该清除手动标记**，让数据重新从黑色开始

### 修复内容

#### 1. 单张 AI 推理时清除标记

**文件：** `views/labeling/label_widget.py:6290-6291`

```python
# Clear manually_edited flag when AI re-inference
self.other_data["manually_edited"] = False
```

#### 2. 批量 AI 推理时清除标记

**文件：** `views/labeling/utils/batch.py:204-213, 234`

```python
# 更新已存在文件
if replace:
    data["shapes"] = new_shapes
    data["description"] = new_description
    data["manually_edited"] = False  # 清除标记
else:
    data["shapes"].extend(new_shapes)
    ...
    data["manually_edited"] = False  # 清除标记

# 新建文件
data = {
    ...
    "manually_edited": False,
}
```

#### 3. 保存时恢复黑色

**文件：** `views/labeling/label_widget.py:4658-4660`

```python
if self.other_data.get("manually_edited", False):
    color = self._config.get("manually_edited_color", "#FFA500")
    item.setForeground(QtGui.QColor(color))
else:
    # Reset to default color (black) when not manually edited
    item.setForeground(QtGui.QColor("#000000"))
```

### 修复效果

✅ **单张推理**：AI 推理后清除标记，文件变黑色
✅ **批量推理**：AI 批量推理后清除所有标记，所有文件变黑色
✅ **颜色更新**：保存后正确更新文件列表颜色
✅ **导出正确**：只导出当前模型推理不准、需要人工修正的数据

### 完整流程示例

```
1. AI 推理 → 黑色（manually_edited = false）
2. 手动修改 → 橙色（manually_edited = true）
3. 再次 AI 推理 → 黑色（manually_edited = false）✅
4. 如果 AI 还是不准 → 再次手动修改 → 橙色
```
